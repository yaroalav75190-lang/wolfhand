# Чек-лист запуска акции «Рука волка»

Продукт готов и протестирован. Ниже — то, что должно быть сделано **вне кода**, прежде чем
включать акцию. Пункты со знаком ⛔ — блокирующие: без них запускаться нельзя.

---

## 1. Юридический блок

- [ ] ⛔ **Уведомление в Роскомнадзор от клуба.** Подаётся бесплатно на pd.rkn.gov.ru,
      занимает ~15 минут. Без него нарушается ст. 22 ФЗ-152. Полученный номер вписывается
      в `docs/consent-pd.html` § 1.
- [ ] ⛔ **Уведомление в Роскомнадзор от каждого партнёра.** Как только контакт участника
      уходит в базу партнёра, партнёр становится самостоятельным оператором ПДн.
      Ответственность несёт он сам, но проследить должен организатор.
- [ ] ⛔ **Соглашение между клубом и каждым партнёром** о порядке обработки персональных
      данных (ч. 3 ст. 6 ФЗ-152): что передаётся, для чего, кто отвечает за защиту,
      как обрабатывается отзыв согласия.
- [ ] ⛔ **Кто налоговый агент по призам дороже 4 000 ₽.** Apple Watch и сертификат LEVVEL
      создают у победителя доход, облагаемый НДФЛ 35% с суммы превышения. Вариантов два:
      партнёр вручает приз сам и оформляет как налоговый агент, либо передаёт приз клубу
      по акту, и агентом становится клуб. Решение фиксируется в договоре.
- [ ] ⛔ **Проверка юристом** четырёх документов в `docs/`: `rules.html`, `consent-pd.html`,
      `consent-partners.html`, `consent-marketing.html`. Поля для заполнения выделены жёлтым.
- [ ] Реквизиты организатора и всех партнёров вписаны в правила (§ 3) и в согласие
      на передачу данных.
- [ ] Даты начала и окончания акции проставлены в правилах (§ 2).

## 2. Призовой фонд

- [ ] ⛔ **Реальный состав фонда согласован с партнёрами** и внесён в `api/_lib/prizes.js`:
      наименование, розничная стоимость, количество штук на всю акцию.
      Сейчас там рабочая заготовка по документу заказчика.
- [ ] Физическое наличие призов подтверждено. Тираж в коде должен совпадать с тем,
      что реально лежит на складе, — иначе система пообещает то, чего нет.
- [ ] Условия сертификатов партнёров зафиксированы: размер скидки, на что распространяется,
      срок действия, складывается ли с другими акциями.
- [ ] Экономика пересчитана под реальный фонд: `node tools/econ.mjs <раздач в месяц>`.
      Если строка «первый приз закончится через N дней» показывает меньше срока акции —
      либо пополнять фонд, либо снижать вес этого исхода.
- [ ] Дневной потолок затрат клуба выставлен: `PRIZE_BUDGET_DAILY_COGS`.

## 3. Техническая подготовка

- [ ] Домен куплен, DNS указывает на сервер.
- [ ] `./deploy-scripts/deploy.ps1 -ServerIp <IP> -SshUser root -Domain <домен>` выполнен,
      HTTPS работает — без него не запустится сканер QR у сотрудников.
- [ ] `.env.production` заполнен: `WOLF_SESSION_SECRET`, пароли ролей, пароль на каждого партнёра.
- [ ] ⛔ **`DEV_MODE=0`** — при `1` через API можно заказать любую комбинацию.
- [ ] Бэкап базы настроен: `deploy-scripts/backup-wolfhand.sh` в cron.
- [ ] Полный путь проверен на проде: скан QR → регистрация → подтверждение на стойке →
      раздача → выдача приза → погашение сертификата.

## 4. Материалы для точек

- [ ] Логотип получен в SVG или PNG — в Drive лежат только `.ai` и `.pdf`.
- [ ] Тейбл-тенты распечатаны: `/admin/print.html` → «Печать всех листов».
      У каждой точки **свой** QR: перепечатать чужой — значит отдать ему весь свой трафик.
- [ ] Роллапы и QR-карточки размещены в клубе.
- [ ] На материалах есть обязательное по ст. 9 ФЗ-38: сроки, организатор, где смотреть правила,
      «количество призов ограничено», 18+.
- [ ] Интернет-креативы промаркированы через ОРД.

## 5. Люди

- [ ] ⛔ **У каждого партнёра назначен ответственный за выдачу QR.** Это главный риск проекта:
      акции такого типа обычно проваливаются не по технике, а потому что персонал через пару
      дней перестаёт выдавать коды. Здесь точек пять, и в четырёх работают чужие сотрудники.
- [ ] Персонал стойки обучен — `ИНСТРУКЦИЯ_СТОЙКА.md`, десять минут.
- [ ] Партнёрам переданы доступы в кабинет и `ИНСТРУКЦИЯ_ПАРТНЁРА.md`.
- [ ] Назначен ответственный за ежедневный просмотр витрины в первую неделю.

## 6. Первая неделя после запуска

- [ ] Каждый день смотреть витрину: сканы по каждой точке, конверсии «скан → регистрация»
      и «регистрация → визит».
- [ ] **Ноль сканов у точки два дня подряд — материалы не выложены или сотрудник молчит.**
      Это операционная проблема, решается звонком, а не доработкой.
- [ ] Сверять фактическое распределение комбинаций с ожидаемым (вкладка «Обзор»).
      Устойчивый перекос на сотнях раздач — повод посмотреть веса.
- [ ] Проверять, доходят ли сертификаты до касс партнёров. Стабильный ноль в графе
      «погашено» означает, что партнёр не знает, что с ними делать.
- [ ] Следить за очередью выдач: крупные призы не должны висеть невручёнными.
